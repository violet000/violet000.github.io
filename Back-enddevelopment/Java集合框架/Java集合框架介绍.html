集合框架总览

  • BACK-ENDDEVELOPMENT
  • JAVA集合框架
  • JAVA集合框架介绍

一、为什么需要 Java 集合框架？

在实际开发中，如果只靠数组来存储数据，会遇到很多问题：

  • 长度固定：数组一旦创建长度不能改变，扩容很麻烦
  • 操作不统一：没有统一的增删改查接口，容易写重复代码
  • 功能不足：排序、查找、去重等都需要自己实现

Java 集合框架（Java Collections Framework, JCF） 就是为了解决这些问题而设计的一套统一的、可扩展的集合 API 体系：

  • 提供统一的接口（List、Set、Map 等）
  • 内置常用数据结构（动态数组、链表、哈希表、红黑树、队列、堆等）
  • 提供通用算法（排序、反转、查找、同步包装等）

掌握集合框架 = 掌握常用数据结构 + Java 实现方式 + 面试高频考点。

二、Java 集合体系总体框架

Java 集合大体分为两大体系：

  • Collection 体系 —— 单值存储（强调“元素”）
  • Map 体系 —— 键值对存储（强调“映射关系”）

1. 顶层结构示意

  • Iterable：可被 for-each 遍历的最顶层接口（Collection 继承它）
  • Collection：单列集合根接口
  • Map：双列集合根接口，独立体系

三、Collection 体系概览

1. List：有序、可重复（“列表”）

特点：

  • 维护元素插入顺序（有序）
  • 允许存储重复数据
  • 允许元素为 null
  • 支持按下标随机访问

常见实现类：

  • ArrayList —— 动态数组
    • 读多写少场景优先（查询 O(1)，插入/删除中间元素 O(n)）
    • 有扩容机制，默认扩容 1.5 倍
  • LinkedList —— 双向链表
    • 适合频繁插入/删除（尤其是首尾），随机访问较慢
    • 还实现了 Deque，可用作双端队列、栈
  • Vector
    • 早期的线程安全 List（方法带 synchronized）
    • 性能较差，新项目中基本被 ArrayList + Collections.synchronizedList 替代

典型使用场景：

  • 维护有顺序要求的数据，如：消息列表、操作记录
  • 需要通过下标快速访问元素的场景

2. Set：无序（或有序）、不可重复（“集合”）

总体特点：

  • 元素不允许重复
  • 去重依赖 hashCode() 和 equals()（或比较器）

常见实现类：

  • HashSet
    • 底层基于 HashMap，元素无序
    • 依赖哈希值实现快速查找与去重
  • LinkedHashSet
    • 在 HashSet 基础上增加双向链表
    • 可记住插入顺序
  • TreeSet
    • 底层基于红黑树
    • 可排序（自然顺序或自定义比较器）

典型使用场景：

  • 对数据去重（如去重用户 ID、去重标签）
  • 需要按排序结果输出时使用 TreeSet

3. Queue / Deque：队列体系

Queue（队列）：

  • 一般为单端队列：FIFO（先进先出）
  • 常见操作：offer、poll、peek

Deque（双端队列）：

  • 两端都可进出队
  • 既可以当队列用，也可以当栈（LIFO）用

典型实现：PriorityQueue

  • 底层基于堆结构
  • 每次出队的是“优先级最高（或最低）”的元素，而不是插入最早的元素
  • 常用于任务调度、定时任务、排行榜等

注意：

  • 并发环境下要优先考虑 BlockingQueue 及 java.util.concurrent 包中的并发集合

四、Map 集合体系 —— 键值对映射结构

Map 以键值对形式存储数据：

核心特性：

  • key 在同一个 Map 中唯一
  • value 可以重复，也可以为 null（视具体实现而定）
  • 常用操作：put、get、remove、containsKey 等

1. 常见实现类及特点

Map 实现 底层结构 key/value 是否允许 null 主要特点
HashMap 数组 + 链表 + 红黑树 允许 最常用，性能好，无序
LinkedHashMap HashMap + 双向链表 允许 维护插入顺序/访问顺序
TreeMap 红黑树 不允许 null key 可排序（按 key 排序）
Hashtable 数组 + 链表（线程安全） 不允许 早期实现，已不推荐
ConcurrentHashMap 分段/分桶锁 + 链表/红黑树 不允许 null key/value 高并发场景下的首选 Map 实现

典型使用场景：

  • 配置项、环境变量等 key-value 数据
  • 需要根据 key 快速查找 value 的场景
  • 缓存、索引、统计计数（如 Map<String, Integer>）

五、Collection 与 Collections 的区别

这一对是面试高频考点，要能一句话说清。

1️⃣ Collection

  • 是 接口
  • 位于 java.util 包
  • 是集合体系的 根接口

包含三大子接口：

  • List
  • Set
  • Queue

👉 作用：定义集合的基本操作规范，不提供具体实现。

常见方法（部分）：

  • add(E e)、remove(Object o)
  • size()、isEmpty()
  • iterator()

2️⃣ Collections

  • 是 工具类（final class）
  • 所在包仍为 java.util
  • 不能被实例化
  • 内部全是 static 方法

👉 作用：提供对集合的通用算法支持和辅助方法。

常用方法示例：

  • 排序：Collections.sort(list)
  • 反转：Collections.reverse(list)
  • 最大/最小值：Collections.max(collection)、Collections.min(collection)
  • 打乱顺序：Collections.shuffle(list)
  • 线程安全包装：
    • Collections.synchronizedList(list)
    • Collections.synchronizedMap(map)
  • 不可变集合（早期用法）：Collections.unmodifiableList(list) 等

📌 高频对比表：

对比点 Collection Collections
类型 接口 工具类
职责 描述“是什么” 提供“怎么操作”
是否有子接口 有（List/Set/Queue） 无
是否包含静态方法 几乎没有 全是静态方法
关注点 抽象数据结构 算法与工具方法

一句话记忆：

Collection 是“容器规范”，Collections 是“操作容器的工具箱”。

六、一些核心特性与容易被问到的点

1. 泛型在集合中的作用

  • 集合几乎都配合 泛型 使用，如：List<String>、Map<String, Integer>
  • 优点：
    • 编译期类型检查，避免运行时 ClassCastException
    • 不需要频繁强制类型转换

2. Fail-Fast 机制

  • 大部分非并发集合（如 ArrayList、HashMap）的迭代器是 fail-fast 的
  • 在遍历过程中，如果结构被“非迭代器方式”修改（如其他线程直接 add/remove），会抛出 ConcurrentModificationException
  • 解决方式：
    • 使用并发集合（ConcurrentHashMap、CopyOnWriteArrayList 等）
    • 或者遍历时使用迭代器自身的 remove() 方法

3. 线程安全与非线程安全

  • 大部分基础集合（如 ArrayList、HashMap）默认不是线程安全的
  • 线程安全方案：
    • 使用 Collections.synchronizedXXX() 进行包装
    • 或直接使用 java.util.concurrent 包下的并发集合
      • 如 ConcurrentHashMap、CopyOnWriteArrayList、BlockingQueue 等

七、面试重点与回答模板

以下答案可直接背诵 + 视情况扩展。

⭐ 1. Java 集合框架的设计思想？

👉 回答思路：接口 → 抽象类 → 实现类 → 工具类 → 解耦 & 复用

示例答案：

Java 集合框架采用接口与实现分离的设计思想：

  • 顶层接口：定义行为规范（如 List、Set、Map）
  • 抽象类：提供部分通用实现（如 AbstractList、AbstractMap）
  • 具体实现类：针对不同场景做性能权衡（如 ArrayList、LinkedList、HashMap）
  • 算法与结构分离：通过 Collections 工具类提供排序、查找、同步包装等算法

优点：

  • 高内聚、低耦合
  • 使用者只关心接口，不关心底层具体实现
  • 方便扩展新集合类型，提升代码复用性和可维护性

⭐ 2. Collection 和 Map 的区别？

对比项 Collection Map
数据结构 单值 键值对（key-value）
元素唯一性 由具体实现决定 key 必须唯一，value 可重复
继承体系 继承 Iterable 独立体系
存储方式 只存一个元素 同时存 key 和 value
是否允许重复 List 允许重复 value 可重复，key 不重复

高分回答模板：

Collection 注重存储元素本身，是单列集合；
Map 注重维护 key 与 value 的映射关系，是双列集合；
Collection 继承自 Iterable，可以直接用于增强 for 循环遍历，而 Map 需要先获取 keySet 或 entrySet 再遍历。

⭐ 3. List 和 Set 的区别？

答题要点：是否有序、是否可重复、典型实现类与使用场景。

示例答案：

  • List：有序、可重复，支持通过下标随机访问，典型实现有 ArrayList、LinkedList
  • Set：通常无序（HashSet）、不可重复，用于去重，部分实现有序或可排序（LinkedHashSet、TreeSet）

可以补一句场景：

需要保持插入顺序、允许重复时用 List；
需要去重或只关心“是否存在”时用 Set。

⭐ 4. ArrayList 和 LinkedList 的区别？（简版）

  • 底层结构不同：
    • ArrayList：动态数组
    • LinkedList：双向链表
  • 随机访问性能：
    • ArrayList 按下标访问时间复杂度 O(1)
    • LinkedList 需要从头或尾遍历，O(n)
  • 插入/删除性能：
    • ArrayList 在中间插入/删除，需要移动大量元素，O(n)
    • LinkedList 只需修改前后指针，O(1)（在定位到节点之后）

总结一句：

读多写少选 ArrayList，频繁插入/删除选 LinkedList（但实际开发中绝大多数场景仍是 ArrayList）。

⭐ 5. HashMap 和 Hashtable、ConcurrentHashMap 的简单对比

  • HashMap
    • 线程不安全
    • 允许 null key 和 null value
    • 性能好，是最常用的 Map 实现
  • Hashtable
    • 所有方法基本都加了 synchronized，线程安全但粗粒度
    • 不允许 null key 或 null value
    • 设计较早，已不推荐新项目使用
  • ConcurrentHashMap
    • 为高并发场景设计的 Map
    • 通过分段锁/分桶锁等机制提高并发性能
    • 不允许 null key 或 null value

一句话总结：

单线程或读多写少用 HashMap，并发场景用 ConcurrentHashMap，Hashtable 基本是历史包袱。

八、学习与实战建议

  • 先整体 → 再局部：先看清接口体系图，再逐个突破 List、Set、Map
  • 先接口 → 再实现类：先记住每个接口的语义，再记忆典型实现及底层结构
  • 结合数据结构：把 ArrayList 对应“动态数组”、LinkedList 对应“链表”、HashMap 对应“哈希表 + 红黑树”
  • 多画图、多对比：画出 HashMap 的数组 + 链表/红黑树结构，加深记忆
  • 多写代码验证：
    • 自己写 demo 验证插入顺序、是否排序、是否允许 null
    • 在遍历时故意修改集合，观察 fail-fast 行为
