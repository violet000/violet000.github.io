一、Map 接口体系总览

1. Map 的核心特点

  • 以 Key-Value 形式存储
  • key 唯一，value 可重复
  • 允许 null 键与 null 值（不同实现不同）
  • 根据实现不同可：有序 / 无序 / 排序
  • 迭代器多为 fail-fast（结构被并发修改时抛 ConcurrentModificationException）

2. 常见实现

  • HashMap —— 最常用
  • LinkedHashMap —— 有序 HashMap
  • TreeMap —— 排序 Map
  • Hashtable —— 早期同步 Map（不推荐）
  • ConcurrentHashMap —— 并发容器

二、HashMap（重点）

1. 底层结构

JDK 7：数组 + 链表
JDK 8：数组 + 链表 + 红黑树

2. 默认参数

  • 初始化容量：16
  • 加载因子：0.75
  • 扩容方式：容量 × 2
  • 触发扩容：size > capacity * loadFactor
  • 预估容量：new HashMap<>((int)(expectedSize / 0.75f) + 1)

  5. size 超阈值 → resize 扩容 + rehash

4. Hash 冲突解决方案

  • 拉链法（数组 + 链表）
  • 当链表长度 ≥ 8 且数组长度 ≥ 64 时树化为红黑树
  • 桶节点数量 < 6 时会退化回链表（untreeify）

5. 非线程安全体现

  • put 导致数据覆盖
  • 扩容导致死循环（JDK7）
  • size 统计错误
  • 失败的读写不可见

6. 允许

  • key = null
  • value = null
  • 但只允许一个 null key（由哈希桶决定）

7. 常见坑位

  • 可变对象作 key，修改后 hash 改变导致“找不到”或重复存储
  • 迭代时结构被修改 → fail-fast 异常
  • 盲目扩容/默认容量，导致频繁 resize，影响性能
  • 键的 equals/hashCode 不一致或未重写，造成冲突/重复存储

8. 并发替代

  • 不要用 Hashtable；优先 ConcurrentHashMap
  • 低并发可用：Collections.synchronizedMap(new HashMap<>())（整体锁，吞吐低）

三、LinkedHashMap

1. 底层结构

  • HashMap + 双向链表

2. 特点

  • 插入顺序/访问顺序可选
  • 遍历顺序稳定
  • 保留 HashMap 的 O(1) 平均查找
  • 允许一个 null key、多个 null value

四、TreeMap

1. 底层：红黑树

2. 排序规则

  • key 实现 Comparable
  • 或传入 Comparator

3. 特点

  • 自动排序
  • 不允许 null key
  • 时间复杂度：O(logN)
  • 迭代有序，支持范围查询：subMap / headMap / tailMap / ceiling / floor
  • Comparator/Comparable 必须自反、传递、与 equals 一致，否则会出现排序异常或看似重复

4. 并发替代

  • 无内置线程安全
  • 需要有序并发：ConcurrentSkipListMap

五、Hashtable（已过时，不推荐）

特点

  • JDK 1.0 遗留产物
  • 线程安全 —— synchronized 整体锁
  • 性能差
  • 不允许 null key 和 null value
  • 迭代弱一致，但锁粒度大导致吞吐差

替代方案

✔ ConcurrentHashMap
✔ Collections.synchronizedMap()

六、ConcurrentHashMap

1. 作用

  • 支持高并发
  • 线程安全 Map
  • 不允许 null key/value，避免歧义

2. JDK7 实现

  • Segments 分段锁
  • ReentrantLock

3. JDK8 实现（重点）

  • Node 数组 + 链表 + 红黑树
  • CAS + synchronized
  • 更细粒度锁

4. 为什么更快？

  • 放弃分段锁
  • 更少锁竞争
  • 使用 CAS 乐观锁
  • 红黑树加速查询
  • 桶级 synchronized，比全表锁粒度小

5. 其他要点

  • size / forEach 为弱一致视图（不会抛 fail-fast）
  • compute/putIfAbsent/merge 原子复合操作，避免双重检查竞态
  • 预估并发度：new ConcurrentHashMap<>(initialCapacity)

1️⃣ HashMap 是如何定位数组下标的？

答：通过 hash 扰动函数 + 位运算：

2️⃣ HashMap 线程不安全表现在哪里？

  • put 数据丢失
  • 扩容死循环（JDK7）
  • 多线程 size 不准确
  • 读到旧数据

3️⃣ ConcurrentHashMap 如何实现线程安全？

JDK7：分段锁
JDK8：

  • CAS
  • synchronized
  • 红黑树
  • Node 数组
  • 分桶锁粒度

4️⃣ HashMap 与 ConcurrentHashMap 的区别？

  • 线程安全：前者否，后者是（桶级锁/CAS）
  • 允许 null：前者允许，后者不允许
  • 迭代一致性：前者 fail-fast，后者弱一致
  • 性能：前者单线程快；并发场景后者优先

需要顺序 LinkedHashMap
需要排序 TreeMap
高并发 ConcurrentHashMap
并发有序 ConcurrentSkipListMap
不推荐 Hashtable
