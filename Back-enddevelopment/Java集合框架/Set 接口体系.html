一、Set 接口体系概览

1. Set 的核心特性

  • 不允许存储重复元素（由 equals 定义唯一性）
  • 最多包含一个 null 元素（TreeSet 不允许）
  • 无索引，不能通过下标访问
  • 关注的是 “是否存在” 而非位置
  • 迭代器普遍为 fail-fast（修改结构后再遍历会抛 ConcurrentModificationException）

2. 常见实现类

  • HashSet —— 哈希表
  • LinkedHashSet —— 哈希表 + 双向链表（有序）
  • TreeSet —— 红黑树（有序，可排序）

二、HashSet

1. 底层结构

  • 基于 HashMap 实现
  • 元素实际存放在 HashMap 的 key 中
  • value 统一为：Object PRESENT = new Object();

2. 重要特性

  • 元素唯一
  • 无序（hash 决定位置）
  • 允许一个 null

3. 如何判断重复元素？

依赖两个方法：

  1. hashCode() —— 判断桶位置
  2. equals() —— 判断是否同一对象

规则：

  • hashCode 不同 → 一定不等
  • hashCode 相同 → 还要 equals 判断

4. 必须重写

5. 哈希冲突解决

  • 数组 + 链表（JDK 7）
  • 数组 + 链表 + 红黑树（JDK 8，链表长度 ≥ 8 且容量 ≥ 64 时树化）

6. put 流程（简化源码版）

  1. hash(key) 计算桶下标
  2. 桶为空 → 直接放入
  3. 桶非空 → equals 判断是否已有相同元素
  4. 链表插入或红黑树插入
  5. size 超阈值 → resize 扩容再重哈希

7. 性能参数（与 HashMap 一致）

  • 默认容量：16；默认装载因子：0.75
  • 触发扩容：size > capacity * loadFactor
  • 扩容成本：需要重新 hash，尽量预估容量 new HashSet<>(expectedSize / 0.75f + 1)

8. 线程安全

  • 非线程安全
  • 线程安全包装：Collections.synchronizedSet(new HashSet<>())
  • 高并发场景：使用 ConcurrentHashMap + Collections.newSetFromMap(...) 或 JDK 提供的 ConcurrentSkipListSet（有序）

9. 常见坑位

  • 忘记重写 equals/hashCode，导致“看似相同但存成两个元素”
  • 可变对象放入 Set 后修改影响 hashCode，可能导致元素“丢失”或查找失败

三、LinkedHashSet

1. 底层实现

  • 继承 HashSet
  • 使用 LinkedHashMap 实现

2. 结构组成

  • 哈希表 + 双向链表

3. 特点

  • 有序（按插入顺序）
  • 性能略低于 HashSet
  • 适合需要“顺序 + 去重”的场景
  • 支持构造时指定 accessOrder=true，实现 LRU 风格的“最近访问顺序”

4. 典型用途

  • 缓存或最近访问记录（保序去重）
  • 序列化或导出时希望顺序稳定
  • 简易 LRU：new LinkedHashSet<>(16, 0.75f, true)

四、TreeSet

1. 底层结构

  • 红黑树（自平衡排序二叉树）
  • 基于 TreeMap 实现

2. 排序方式

两种方式任选其一：

✔ 元素实现 Comparable
✔ 创建 TreeSet 时传入 Comparator

3. 特点

  • 有序
  • 可排序
  • 不允许 null（会抛异常）
  • Comparator/Comparable 必须自反、传递、与 equals 一致，否则会出现“看似不重复但被当重复”或排序异常

5. 线程安全

  • 非线程安全
  • 需要并发有序：ConcurrentSkipListSet

6. 典型用途

  • 需要“有序 + 去重”：排名、排行榜、区间查询（如 subSet/headSet/tailSet）
  • 需要按范围取值：subSet(from, to)、first/last、higher/lower

4. 示例

五、三者对比

集合 有序性 底层结构 是否可排序 线程安全
HashSet 无序 HashMap 否 否
LinkedHashSet 插入/访问有序 HashMap + 链表 否 否
TreeSet 有序（可排序） 红黑树 是 否

补充：

  • 并发有序：ConcurrentSkipListSet
  • 并发无序：Collections.newSetFromMap(new ConcurrentHashMap<>())

六、面试重点（高频面试题系列3）

1. HashSet 如何保证元素唯一？

答：依赖 hashCode + equals

流程：

  1. 计算 hashCode 定位桶
  2. 比较 equals 判断是否重复
  3. JDK 1.8 冲突多时树化

2. HashSet 和 TreeSet 的区别？

对比点 HashSet TreeSet
底层结构 哈希表 红黑树
是否排序 否 是
性能 O(1) O(logN)
null 允许 不允许
原理 哈希 比较器

3. 如果不重写 equals() 会发生什么？

答：可能出现“看似相同但被当成不同对象”

示例：

原因：

  • 默认 Object.equals() 比较地址
  • 不是内容相等

4. 可变对象放入 HashSet 后被修改会怎样？

  • 如果修改了参与 hashCode/equals 的字段，元素可能“找不到”或重复插入
  • 规避：放入 Set 后不要改关键字段，或使用不可变对象

5. 为什么迭代时修改集合会抛异常？

  • 因为迭代器是 fail-fast 的，结构修改后 modCount 变化，next 时检测到即抛 ConcurrentModificationException
  • 规避：使用 Iterator.remove()，或使用并发集合（如 CopyOnWriteArraySet / ConcurrentSkipListSet）

七、适用场景总结

场景 推荐
需要快速去重 HashSet
需要有序去重 LinkedHashSet
需要排序 TreeSet
要求线程安全 Collections.synchronizedSet
