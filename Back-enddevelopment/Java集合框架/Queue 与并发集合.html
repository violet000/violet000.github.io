一、队列接口体系

1. Queue（单向队列）

  • 先进先出（FIFO）
  • 只允许在队尾插入，在队头删除
  • 常用方法：
    • add() / offer() — 入队
    • remove() / poll() — 出队
    • element() / peek() — 查看队头元素
  • 迭代器多数为 fail-fast，遍历期间结构被修改将抛 ConcurrentModificationException

👉 区别：

方法 失败时行为
add/remove/element 抛异常
offer/poll/peek 返回特殊值（false/null）

2. Deque（双端队列）

  • 两端都可以插入与删除
  • 既可以当 队列 也可以当 栈
  • 典型实现：
    • ArrayDeque
    • LinkedList
  • ArrayDeque 一般优于 Stack/LinkedList 做栈/队列（更快、无容量开销）
  • 不允许 null 元素

3. BlockingQueue（阻塞队列）

  • 支持两个特性：
    • 队列满 → 阻塞生产者
    • 队列空 → 阻塞消费者
  • 常用于：生产者-消费者模型
  • 常见超时/返回值 API 便于服务降级和背压
  • 迭代弱一致，不会 fail-fast

提供四类 API：

操作 抛异常 返回状态 阻塞等待 超时等待
插入 add offer put offer(e,time)
删除 remove poll take poll(time)

二、阻塞队列

1. ArrayBlockingQueue

  • 有界数组实现
  • 需要指定固定长度
  • 内部为：循环数组
  • 使用一把 ReentrantLock
  • 支持公平锁/非公平锁
  • 可配合 offer+超时实现限流
  • 公平锁降低吞吐但更公平

👉 适合：

  • 限流
  • 背压
  • 有界缓冲

2. LinkedBlockingQueue

  • 链表结构
  • 默认无界（理论上 Integer.MAX_VALUE）
  • 两把锁：
    • 入队锁
    • 出队锁
  • 并发度更高
  • 可指定容量上限：new LinkedBlockingQueue<>(capacity)
  • 节点多会增加 GC 压力

👉 注意：

  • 无界队列可能 OOM
  • 适合生产速度≈消费速度

3. PriorityBlockingQueue

  • 支持优先级
  • 基于 堆结构
  • 元素需要实现 Comparable
  • 无界队列
  • 比较器/Comparable 不应与 equals 冲突，否则会出现“看似重复但允许插入”

👉 使用场景：

  • 任务调度
  • 延时执行

4. DelayQueue

  • 优先级队列 + 时间延迟
  • 底层：PriorityQueue
  • 元素实现 Delayed 接口
  • 取元素时若未到期会阻塞

👉 使用场景：

  • 订单超时关闭
  • 缓存失效
  • 定时任务

示例：

5. SynchronousQueue

  • “零容量”队列，put 必须等待 take 配对
  • 支持公平/非公平模式
  • 典型用途：直接移交（handoff），如线程池 SynchronousQueue 以推动线程快速创建/回收

6. LinkedTransferQueue

  • 无界链表 + CAS，支持 transfer 立即交付或等待消费者
  • 具备队列 + 直接移交双重能力
  • 适合高并发下的“有消费者即交付”

三、并发集合

1. CopyOnWriteArrayList（写时复制）

  • 读多写少场景
  • 底层：数组 + 加锁写
  • 写操作：
    1. 复制新数组
    2. 修改新数组
    3. 替换引用

👉 特点：

  • 读无锁
  • 避免 ConcurrentModificationException
  • 内存占用大
  • 迭代基于快照，读到的是旧数据

❌ 不适合：

  • 写频繁
  • 大对象

2. ConcurrentLinkedQueue

  • 无界队列
  • 基于 链表 + CAS
  • 非阻塞算法

👉 特点：

  • 高并发性能好
  • 无锁
  • 不是阻塞队列！
  • 元素可能较多导致 GC；不适合需要背压的场景

3. ConcurrentSkipListMap

  • 并发版 TreeMap
  • 底层：跳表
  • 自动排序
  • 支持范围查询
  • 迭代弱一致，不抛 fail-fast
  • 不允许 null key / null value

👉 适合：

  • 排序 + 并发
  • 红黑树替代品

2️⃣ 为什么 ArrayBlockingQueue 适合限流场景？

✔ 有界队列
✔ 队满阻塞生产者
✔ 防止 OOM

3️⃣ SynchronousQueue 与 ArrayBlockingQueue 的区别？

  • 容量：前者 0，后者固定 >0
  • 行为：前者必须生产/消费配对交付；后者可缓冲
  • 适用：前者用于直接移交或线程池；后者用于削峰/排队
