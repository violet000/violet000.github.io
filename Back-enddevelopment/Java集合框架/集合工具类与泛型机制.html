一、Collections 工具类（操作集合的工具库）

1.1 Collections 是什么？

  • 所属包：java.util.Collections
  • 本质：工具类，内部都是静态方法
  • 作用：对 Collection/Map 等集合进行操作

👉 千万不要和 Collection 接口混淆

1.2 常见功能汇总

✔ 排序操作

  • Collections.sort(List)
  • 默认按 自然顺序（Comparable）
  • 或传入 Comparator 自定义规则

✔ 反转集合

✔ 最大值/最小值

✔ 线程安全包装（重要）

特点：

  • 内部使用 synchronized
  • 粒度粗 → 性能低
  • 面试对比：ConcurrentHashMap

✔ 不可变集合

特点：

  • 只读视图
  • 修改将抛异常：UnsupportedOperationException
  • 常见用途：防止外部修改内部集合

四、泛型通配符 —— extends 与 super（面试重灾区）

✔ ? 通配符

表示 不确定类型

只能：

  • 读
    不能：
  • 写（null 除外）

✔ ? extends T —— 上界通配符

👉 “只能读不能写”

特点：

  • 只能读取为 Number
  • 不能写入任何子类对象

📌 理解：

生产者用 extends（Producer Extends）

✔ ? super T —— 下界通配符

👉 “能写不能读（读只能 Object）”

用途：

  • 限定参数类型下限
  • 常用于 写入子类数据

📌 理解：

消费者用 super（Consumer Super）

五、面试高频题整理

① Collection 和 Collections 区别？

Collection Collections
接口 工具类
集合根接口 提供静态方法
无实现 包含排序、同步等操作

② Arrays.asList() 有什么坑？

  • 返回 定长 List
  • 不能 add/remove
  • 底层仍是数组

③ 泛型擦除是什么？

  • Java 泛型只存在编译期
  • 运行时会 擦除类型信息
  • 底层仍然是 Object

④ ? extends 与 ? super 区别？

写入 读取
super 能写 extends 能读
super 不能安全读 extends 不能安全写

口诀：

PECS 原则
Producer — Extends
Consumer — Super
