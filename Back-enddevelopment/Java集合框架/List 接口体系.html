一、List 接口体系概览

List 是一个 有序、可重复 的集合，核心特点：

  • 元素有索引（从 0 开始）
  • 允许存储重复元素
  • 允许存储 null
  • 支持按位置访问元素（下标随机访问）

常见实现类总览

实现类 底层结构 是否线程安全 随机访问性能 插入删除性能 典型使用场景
ArrayList 动态数组 否 高效 中间较慢 读多写少
LinkedList 双向链表 否 较差 插入删除高效 插入删除操作较多
Vector 动态数组 是 一般 一般 早期线程安全场景

记忆一句话：绝大多数业务场景用 ArrayList，极少数频繁插入删除用 LinkedList，Vector 主要存在于老代码和面试题里。

二、ArrayList —— 动态数组结构

1. 底层结构与特性

  • 基于 动态数组 Object[] 实现
  • 支持 **随机访问 O(1)**，适合频繁按索引读取
  • 连续内存存储，CPU 缓存友好，遍历性能好

常见操作时间复杂度（n 为元素个数）：

  • 按索引访问：O(1)
  • 尾部插入：均摊 O(1)
  • 头部或中间插入/删除：O(n)（需要搬移元素）

2. 扩容机制（JDK 8 之后）

默认容量与初始化方式：

  • 无参构造：延迟初始化（第一次 add 时扩容为 10）
  • 有参构造：直接创建指定容量数组，如 new ArrayList<>(100)

扩容规则（简化理解）：

扩容步骤：

  1. 创建更大的新数组
  2. 将旧数组数据拷贝到新数组
  3. 将内部引用指向新数组

👉 扩容是一个 昂贵操作，涉及：

  • 新数组分配
  • 元素整体拷贝
  • 可能触发 GC

实践建议：

  • 能预估元素数量时，优先：new ArrayList<>(initialCapacity)
  • 大数据场景下，合理预估容量可以明显减少扩容带来的抖动

3. 常用方法与 subList 注意事项

常用方法：

  • 增：add(E e)、add(int index, E element)
  • 删：remove(int index)、remove(Object o)
  • 改：set(int index, E element)
  • 查：get(int index)、indexOf(Object o)、lastIndexOf(Object o)
  • 其他：subList(int from, int to)、ensureCapacity(int minCapacity)、trimToSize()

subList 的常见坑：

  • subList 返回的是 视图（view），不是全新 List
  • 对 subList 结构修改会影响原 List，反之亦然
  • 原 List 结构改变后再操作 subList，可能出现 ConcurrentModificationException

面试可说的安全用法：

如需得到真正独立的子列表，可使用：new ArrayList<>(list.subList(from, to))。

4. 适用/不适用场景

适合：

  • 读多写少的场景
  • 需要大量按索引随机访问
  • 插入删除主要集中在尾部

不适合：

  • 频繁在头部或中间插入、删除元素
  • 强依赖实时插入/删除性能的队列/栈（可考虑 LinkedList 或并发集合）

三、LinkedList —— 双向链表结构

1. 底层结构

  • 基于 双向链表 实现
  • 节点结构大致为：
  • 通过 first 和 last 引用分别指向头节点和尾节点

2. 时间复杂度

操作 复杂度
头插入/尾插入 O(1)
删除当前节点 O(1)
根据索引访问 O(n)

说明：

  • 若已持有节点引用（例如来自迭代器），删除当前节点是 O(1)
  • 按索引访问时，会从头或尾开始遍历，平均复杂度仍为 O(n)

3. 特性与使用方式

优势：

  • 非常适合频繁插入删除的场景（尤其是首尾）
  • 同时实现了 Deque 接口，可作为：
    • 队列（Queue）
    • 双端队列（Deque）
    • 栈（Stack 的替代实现）

劣势：

  • 不支持高效随机访问
  • 每个节点多出两个指针，内存开销相对数组更大

典型用法示例：

  • 作为队列：offer() / poll() / peek()
  • 作为栈：push() / pop() / peek()

四、Vector —— 线程安全的动态数组（历史遗留）

1. 特点

  • 大部分方法都加了 synchronized 关键字
  • 线程安全，但锁粒度非常粗
  • 底层同样是动态数组
  • 性能普遍逊于 ArrayList

2. 为什么逐渐被淘汰

  • 同步粒度大，无法充分利用多核
  • 与现代并发集合相比，扩展性与性能都较差
  • 存在更优的替代：
    • Collections.synchronizedList(new ArrayList<>())
    • CopyOnWriteArrayList 等并发集合

👉 面试常用表述：

Vector 是 Java 早期的线程安全 List 实现，依靠方法级 synchronized 保证线程安全；
由于性能和扩展性问题，在新项目中基本被 ArrayList + 显式同步 或 并发集合替代。

五、List 遍历方式与 fail-fast 机制

1. 常见三种遍历方式

  • 普通 for（按索引）
    • 优点：可根据索引灵活访问、修改
    • 适合：ArrayList 这类支持 O(1) 随机访问的实现
  • 增强 for（for-each）
    • 底层依赖 Iterator
    • 代码最简洁，但不方便安全删除元素
  • 迭代器（Iterator / ListIterator）
    • Iterator：hasNext() / next() / remove()
    • ListIterator：支持双向遍历，以及遍历过程中的 add()、set() 等操作

2. fail-fast 机制

  • 大部分 List 实现（如 ArrayList、LinkedList）的迭代器都是 fail-fast 的
  • 遍历过程中，如果集合被“非当前迭代器”结构性修改，会抛出 ConcurrentModificationException

常见错误写法（遍历过程中直接调用 list.remove(i)）：

  • 使用增强 for 或迭代器时，直接用 list.remove(...) 来删，会触发 fail-fast

正确做法：

  • 使用迭代器的 remove() 方法
  • 或先记录要删除的元素，遍历结束后统一删除

六、面试高频题（List 专题）

1. ArrayList 和 LinkedList 的区别？

推荐从 5 个角度答：底层结构、时间复杂度、内存占用、线程安全、适用场景。

1）底层结构：

  • ArrayList：动态数组
  • LinkedList：双向链表

2）时间复杂度（大致）：

操作 ArrayList LinkedList
随机访问 O(1) O(n)
头部插入删除 O(n) O(1)
中间插入删除 O(n) O(n)
尾部插入 O(1) 均摊 O(1)

3）内存占用：

  • ArrayList：连续内存，只存数据
  • LinkedList：每个节点多出 prev、next 两个指针，内存开销更大

4）线程安全：

  • 两者默认都 不是线程安全 的

5）适用场景：

  • ArrayList：读多写少、随机访问频繁
  • LinkedList：插入删除多，尤其是首尾

一段可以直接背的总结：

ArrayList 底层是动态数组，随机访问效率高，但在中间插入删除需要移动大量元素；
LinkedList 底层是双向链表，适合频繁插入删除，但按索引访问需要遍历，性能较差。

2. ArrayList 的扩容机制？

必答要点：

  • 默认初始容量 10（第一次插入时分配）
  • 每次扩容大约为 1.5 倍
  • 通过创建新数组 + 拷贝旧数组来完成扩容
  • 建议根据业务场景指定初始容量，减少扩容次数

可扩展点：

  • ensureCapacity(int minCapacity)：手动触发容量检查，避免频繁扩容
  • trimToSize()：将内部数组容量缩减到当前 size，节省内存

3. Vector 为什么不推荐使用？

标准答案要点：

  • 性能低：所有方法都加 synchronized，锁粒度大
  • 扩展性差：难以发挥多核优势
  • 扩容与设计偏陈旧
  • 已被更优集合替代：ArrayList + Collections.synchronizedList / CopyOnWriteArrayList

推荐替代：

  • 单线程：ArrayList
  • 多线程：CopyOnWriteArrayList 或 其他并发集合

🧠 总结：如何选择合适的 List？

结论 解释
频繁查询 → 选 ArrayList 随机访问 O(1)
频繁插入删除 → 选 LinkedList 链表结构插删更高效
多线程场景 → 不用 Vector 更推荐并发集合
大数据场景 → 预估容量 降低扩容次数与成本

一句收尾：实际开发中优先考虑 ArrayList，在少数插删非常密集的场景下用 LinkedList，Vector 基本只需要在面试中把它讲清楚即可。
