一、异常概述

1.1 什么是异常？

  • 程序运行过程中出现的不正常情况
  • Java 使用异常对象来描述错误，并通过抛出（throw）与捕获（catch）机制进行处理
  • 良好的异常处理可以：
    • 提高系统稳定性
    • 提升可维护性和可排错性

1.2 Java 异常体系结构

根类：java.lang.Throwable

  • Error（错误）
    • 系统级错误，通常无法或不建议由程序处理
    • 示例：
      • StackOverflowError
      • OutOfMemoryError
  • Exception（异常）
    • 程序本身可以处理的问题
    • 分为：
      • 编译时异常（Checked Exception）
      • 运行时异常（RuntimeException，Unchecked Exception）

面试常问：“Error 和 Exception 的区别？” → Error 多为系统错误，通常不捕获；Exception 是程序可以处理的异常。

二、异常类型：编译时异常 vs 运行时异常

2.1 编译时异常（Checked Exception）

  • 在编译阶段必须显式处理（要么 try-catch，要么 throws 抛出）
  • 如果不处理，编译器会报错，无法通过编译
  • 常见代表：
    • IOException
    • ClassNotFoundException
    • SQLException

编译时异常通常代表外部环境问题（IO、网络、数据库等），需要调用方显式关注和处理。

2.2 运行时异常（RuntimeException / Unchecked）

  • 继承自 RuntimeException
  • 编译器不强制要求处理
  • 多数是由于程序逻辑错误引起

常见示例：

  • NullPointerException
  • ArrayIndexOutOfBoundsException
  • ArithmeticException
  • ClassCastException
  • NumberFormatException

思路：编译时异常——“外部环境”，运行时异常——“自己写错了”。

3.1 基本语法

3.2 多 catch 分支

注意规则：

  • 子类异常在前，父类异常在后
  • 否则会因“父类异常已捕获所有情况”导致编译错误

3.3 finally 的作用

  • 通常用于资源释放：
    • 关闭文件
    • 关闭数据库连接
    • 关闭网络连接、锁释放等
  • 几乎一定会执行的情况：
    • 正常执行完 try
    • try 或 catch 中抛出了异常
  • 不会执行的情况：
    • System.exit(0) 被调用
    • 进程被强制杀死、物理断电等极端情况

最佳实践：不要在 finally 中写 return 或抛新异常，否则容易掩盖原始异常。

3.4 异常传播机制（调用栈）

  • 当方法中未捕获异常时，异常会沿调用栈向上抛出
  • 直到：
    • 被某一层 try-catch 捕获处理，或
    • 传播到 main 方法仍未捕获 → 程序终止，并打印堆栈跟踪信息（stack trace）

阅读堆栈信息的关键：

  • 从上到下看异常类型与 message
  • 从上往下找到你自己代码的第一行调用位置，往下跟逐步回溯

四、异常链与包装异常

4.1 什么是异常链？

  • 一个异常在处理时，被包装成另一个异常重新抛出
  • 新异常中保存原始异常作为 cause，形成异常链

好处：

  • 不丢失原始异常信息（cause）
  • 对上层暴露更有业务语义的异常类型
  • 方便日志分析与排错

很多框架（如 Spring）大量使用异常链，把底层异常统一包装成自家异常体系。

六、自定义异常

6.1 何时需要自定义异常？

  • 需要表达特定业务语义的错误，例如：
    • UserNotFoundException
    • OrderStatusException
    • BusinessException
  • 便于在业务层捕获与区分不同错误场景

6.2 自定义异常的写法

步骤：

  1. 继承 Exception（编译时异常）或 RuntimeException（运行时异常）
  2. 提供常用构造方法
  3. 可根据需要增加业务字段

选择继承谁：

  • 继承 Exception：强制调用者显式处理（try-catch 或 throws）
  • 继承 RuntimeException：调用者可自由选择是否处理，常用于业务异常

七、finally 与 return 的坑

7.1 finally 中的 return 会覆盖 try 吗？

结论：会覆盖。

返回值：2

原因：

  • try 中的 return 会先计算返回值并保存
  • 然后执行 finally
  • 如果 finally 中再次 return，会覆盖之前保存的返回值

实战建议：**不要在 finally 中写 return 与 throw**，避免掩盖真实问题。

八、try-with-resources（JDK 7+ 推荐写法）

8.1 基本概念

  • 用于简化资源关闭（如流、连接）
  • 要求资源实现 AutoCloseable 接口
  • 语法糖：在 try 语句中声明资源，结束时自动调用 close()

优点：

  • 代码更简洁
  • 避免忘记关闭资源
  • 多个资源按逆序依次关闭

在现代 Java 代码中，优先使用 try-with-resources，而不是手写 finally 关闭流。

✅ 学习与面试建议

  • 多练 debug + 堆栈阅读：学会从异常堆栈中快速定位到自己代码的出错行
  • 画出异常体系结构图：Throwable → Error / Exception → RuntimeException
  • 多写练习：自己实现 1～2 个自定义异常，并在业务代码中使用异常链包装底层异常
  • 面试前至少能流畅回答：Error vs Exception、Checked vs Unchecked、throw vs throws、finally 与 return 的关系、try-with-resources 的好处 等问题
