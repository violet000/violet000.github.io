一、集合体系结构总览

Java 集合大体分为两大体系：

  • Collection：单列集合（只存元素）
  • Map：双列集合（键值对）

1.1 Collection 体系

常见子接口：

  • **List**：有序、可重复，有索引
  • **Set**：无序（或有特定顺序）、不可重复
  • **Queue / Deque**：队列 / 双端队列

1.2 Map 体系

  • 以 key-value 键值对形式存储
  • key 不允许重复，一个 key 最多对应一个 value
  • 常见实现：
    • HashMap
    • LinkedHashMap
    • TreeMap
    • ConcurrentHashMap

1.3 Collection 与 Map 的区别

对比维度 Collection Map
数据结构 单列 双列（key-value）
是否有 key ❌ ✔
是否允许重复 视具体实现（如 List 可） key 不重复，value 可重复
常见实现 List、Set、Queue HashMap、TreeMap 等

二、核心接口与典型实现

2.1 List 接口（有序可重复）

特点：

  • 元素按插入顺序有序
  • 支持索引访问：get(int index)
  • 允许重复元素

典型实现：

  • ArrayList（最常用）
  • LinkedList
  • Vector（老旧，带同步，基本不用）

面试常问：ArrayList vs LinkedList 区别与适用场景。

2.2 Set 接口（不重复）

  • 无索引
  • 不允许重复元素（依靠 hashCode() + equals() 判重）
  • 底层通常基于 Map 实现

常见实现：

  • HashSet：无序，不重复
  • LinkedHashSet：保留插入顺序
  • TreeSet：有序（基于红黑树）

2.3 Queue / Deque 接口

  • Queue：队列，通常先进先出（FIFO）
  • Deque：双端队列，可同时作为队列 & 栈

常见实现：

  • ArrayDeque：高效的双端队列（推荐）
  • PriorityQueue：优先级队列（内部小顶堆）

2.4 栈结构 Stack

  • 后进先出（LIFO）
  • 旧的 Stack 类基于 Vector，不推荐

三、常见集合类与底层实现

3.1 ArrayList vs LinkedList

对比项 ArrayList LinkedList
底层结构 动态数组 双向链表
随机访问（get/set） ✔ O(1) 高效 ❌ O(n)
中间插入 / 删除 ❌ 需要移动大量元素 ✔ 只改链表指针
头部插入 / 删除 ❌ 慢 ✔ 快（操作头节点）
内存连续性 ✔ 连续 ❌ 非连续

适用场景：

  • 读多写少，频繁随机访问 → ArrayList
  • 频繁在头部或中间插入 / 删除 → LinkedList

3.1.1 ArrayList 扩容机制（重点）

  • 默认初始容量：10
  • 当容量不足时进行扩容：
    • 新容量 = 旧容量 × 1.5（newCapacity = old + (old >> 1)）
    • 通过 Arrays.copyOf() 拷贝原数组到新数组
  • 扩容是一个O(n) 的操作，尽量减少扩容次数：
    • 可以在知道大致元素数量时，提前指定初始容量：new ArrayList<>(capacity)

3.2 HashMap、Hashtable、ConcurrentHashMap

3.2.1 HashMap（重点中的重点）

核心结构：

  • JDK 7：数组 + 链表
  • JDK 8：数组 + 链表 + 红黑树

重要参数：

  • 初始容量：默认 16（必须为 2 的幂）
  • 负载因子（loadFactor）：默认 0.75
    • 阈值（threshold）= 容量 × 负载因子

put 流程简述：

  1. 计算 key.hashCode()，再经过扰动函数得到 hash 值
  2. 使用 (n - 1) & hash 计算数组索引（n 为数组长度）
  3. 如果该位置为空，直接插入
  4. 如果不为空：
    • 判断是否与已有节点 hash、equals 相同，相同则覆盖
    • 不同则以链表或红黑树形式挂在该桶后面
  5. 插入后若超过阈值，则进行扩容（数组长度 × 2）

JDK 8 核心变化：

  • 桶上节点数 > 8 时，链表转为红黑树（树化，提高查找效率）
  • 树化条件还要求数组长度 ≥ 64，防止在小表中过早树化
  • 树上节点数下降到 < 6 时，会退化为链表

高频问法：“HashMap 的底层结构？”、“JDK8 做了哪些优化？”、“为什么长度要是 2 的幂？”

3.2.2 Hashtable

  • 所有方法几乎都使用 synchronized 修饰 → 粗粒度锁
  • 线程安全，但性能较低
  • 不允许 null 的 key 和 value
  • 已经基本被 ConcurrentHashMap 取代

3.2.3 ConcurrentHashMap

  • 线程安全的 Map 实现
  • JDK 7：
    • 分段锁（Segment）+ HashEntry 数组
  • JDK 8：
    • 结构与 HashMap 接近：数组 + 链表 + 红黑树
    • 使用 CAS + synchronized 控制并发
    • 更精细的锁粒度，性能更好

面试常问：“HashMap 与 ConcurrentHashMap 的区别？”、“ConcurrentHashMap 为什么比 Hashtable 快？”

3.3 TreeMap 与 LinkedHashMap

3.3.1 TreeMap

  • 基于红黑树实现
  • key 有序：
    • 默认使用 key 的自然顺序（Comparable）
    • 或通过构造方法传入 Comparator
  • 适用于需要按 key 有序遍历的场景（如范围查询）

3.3.2 LinkedHashMap

  • 在 HashMap 基础上，额外维护一条双向链表
  • 可维护两种顺序：
    • 插入顺序
    • 访问顺序（accessOrder=true）
  • 常用于实现 LRU 缓存：

3.4 HashSet、TreeSet、LinkedHashSet

  • HashSet
    • 底层基于 HashMap（元素存到 key，value 用一个固定哨兵对象）
    • 无序、不重复
  • LinkedHashSet
    • 底层基于 LinkedHashMap
    • 保留插入顺序
  • TreeSet
    • 底层基于 TreeMap
    • 元素自动排序（自然顺序或比较器）

记忆：Set 对应的 Hash / LinkedHash / Tree，底层分别对应同名的 Map 版本。

四、底层原理与高频面试点

4.1 HashMap 的哈希冲突与解决

哈希冲突： 不同 key 通过 hash 映射到同一个数组索引。

HashMap 的做法：

  • 使用拉链法：数组 + 链表 / 红黑树
    • 同一个索引上的多个元素组成链表或树
  • JDK 8 之后：
    • 冲突少时使用链表（节省内存）
    • 冲突多时树化为红黑树（提高查找效率）

常见解决哈希冲突的方式对比：

  • 拉链法（HashMap 使用）✔
  • 开放地址法
  • 再哈希法（双重散列）

4.2 ArrayList 的扩容与复杂度

  • 扩容时需要 新建更大数组 + 拷贝旧数组 → 代价较大
  • add(E e) 摊还时间复杂度为 O(1)，但个别触发扩容时为 O(n)
  • remove(index) 需要将后续元素整体左移 → O(n)

因此，在频繁插入 / 删除中间元素的场景下，更适合用 LinkedList 或其他结构。

4.3 Set 为什么不能存重复元素？

  • 多数 Set（如 HashSet）是基于 Map 的 key 实现的
  • Map 要求 key 不重复
  • 判重逻辑依赖：
    • hashCode()：决定分桶位置
    • equals()：在同一桶内最终判断是否“相等”
  • 当两个对象：
    • hashCode 相同
    • equals 返回 true
    • → 认为是同一个元素，不会重复存入

因此：**重写 equals 一定要重写 hashCode**，否则会导致集合行为异常。

4.4 迭代器的 fail-fast 机制

  • 大部分非并发集合（如 ArrayList、HashMap）的迭代器是 fail-fast 的
  • 含义：在遍历过程中，如果检测到集合结构被其他线程 / 非迭代器方式修改，会抛出 ConcurrentModificationException

正确做法：

  • 使用 Iterator 的 remove() 方法
  • 或先收集待删除元素，遍历结束后统一删除
