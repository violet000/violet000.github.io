一、字符串相关类（String、StringBuilder、StringBuffer）

1.1 String：不可变字符串（重点）

核心特点：

  • String 是被 final 修饰的类，不能被继承
  • JDK 8 底层：final char[] value；JDK 9 之后：byte[] + coder
  • 字符串内容不可变（immutable）
  • 有字符串常量池机制

优点：

  • 安全：多线程环境下共享字符串对象不会被修改
  • 可共享：常量池中相同字面量只存一份，节省内存
  • 可作为 HashMap 的键：不可变性保证 hashCode 稳定

面试常见扩展："a" + "b" 与 a + b（其中 a、b 是变量）在编译期 / 运行期的常量池行为不同。

1.2 为什么 String 要设计成不可变？（高频面试）

几个典型理由：

  • 安全性：String 常用于：
    • 类加载（类名）
    • 网络地址、文件路径
    • 数据库连接 URL、用户名等
    • 如果可变，可能被恶意修改，存在安全风险
  • 性能（常量池 + 缓存）：
    • 不可变才能安全地放入常量池中共享
    • 不可变才适合做 hashCode 缓存，提高在 HashMap / HashSet 中的性能
  • 线程安全：
    • 不可变对象天然线程安全，无需额外同步

记忆句：“安全 + 常量池 + 缓存 + 线程安全” = String 不可变的核心原因。

1.3 intern() 方法原理

intern() 用于手动操作字符串常量池：

  • 将当前字符串放入常量池
  • 若常量池中已存在内容相同的字符串，则返回常量池中已有对象的引用

在某些特定场景（如大量重复字符串）中，可以通过 intern() 减少内存占用，但使用不当也会加重常量池压力，一般不建议滥用。

1.4 StringBuilder 与 StringBuffer

用于可变字符串拼接，避免频繁创建 String 对象导致的性能问题。

对比项 StringBuilder StringBuffer
可变性 可变 可变
线程安全 ❌ 不安全 ✔ 线程安全（内部加锁）
效率 高 较低
使用场景 单线程环境 多线程、老代码中使用

日常开发中，**绝大多数场景优先使用 StringBuilder**；StringBuffer 更多出现在老项目或需要兼容旧 API 的地方。

二、常用工具类总览

2.1 Math 数学工具类

全部方法都是 static，直接使用类名调用。

常用方法：

  • Math.abs(x)：绝对值
  • Math.pow(a, b)：幂运算，返回 double
  • Math.sqrt(x)：平方根
  • Math.max(a, b) / Math.min(a, b)：最大 / 最小值
  • Math.random()：生成 [0, 1) 的 double 随机数

注意：Math.random() 底层也使用 Random，但更常用于快速写一行小逻辑。

2.2 Random 随机数类

  • 可生成各种类型随机数：nextInt()、nextLong()、nextBoolean() 等
  • 支持指定种子（seed），相同种子会产生相同序列（便于测试复现）

Java 8 之后还有 ThreadLocalRandom、SplittableRandom 等更高性能随机数类，可在并发场景下使用。

2.3 Arrays 数组工具类

主要用于操作数组：

  • Arrays.sort(arr)：排序
  • Arrays.toString(arr)：输出数组内容
  • Arrays.binarySearch(arr, key)：二分查找（前提：数组已排序）
  • Arrays.copyOf(arr, newLength)：拷贝数组

2.4 Objects 工具类

常用于空指针安全处理：

  • Objects.equals(a, b)：安全比较，内部处理 null
  • Objects.isNull(obj) / Objects.nonNull(obj)：判断空
  • Objects.hash(...)：生成哈希值（常用于重写 hashCode）

2.5 Collections 集合工具类

对 List、Set、Map 等集合进行增强操作：

  • 排序：Collections.sort(list)
  • 最大最小值：Collections.max(list) / Collections.min(list)
  • 线程安全包装：Collections.synchronizedList(list)
  • 不可变集合：Collections.unmodifiableList(list)

Java 9 之后，推荐使用 List.of(...)、Set.of(...) 等更简洁的不可变集合工厂方法。

三、包装类与自动装箱 / 拆箱

3.1 什么是包装类？

将基本数据类型包装成引用类型对象，用于：

  • 与只能接收对象的 API 交互（如集合类）
  • 需要使用 null 表示“无值”时
基本类型 包装类
byte Byte
short Short
int Integer
long Long
float Float
double Double
boolean Boolean
char Character

3.2 自动装箱与拆箱（autoboxing / unboxing）

  • 自动装箱：基本类型 → 包装类型
  • 自动拆箱：包装类型 → 基本类型

装箱 / 拆箱本质上是编译器帮你插入方法调用，频繁装箱拆箱会有性能损耗，循环中要特别注意。

3.3 Integer.valueOf() 与 new Integer() 的区别

  • new Integer(1)：每次都创建新对象，几乎不再推荐使用
  • Integer.valueOf(1)：可能从缓存中复用对象

规范写法：优先使用 valueOf() 或字面量装箱，不要再用 new Integer(...)。

3.4 Integer 缓存机制（重点）

  • 默认缓存范围：[-128, 127]
  • JVM 通过内部类 Integer.IntegerCache 保存这一段整数对应的对象
  • 所有通过 valueOf() 或字面量装箱的值，若在缓存范围内，会复用同一个对象

高频坑：包装类的 == 比较的是“引用是否相同”，而不是值；比较数值大小应使用 equals() 或拆箱后用 ==。

3.5 自动拆箱的空指针问题（常见坑）

当对 null 的包装类型做拆箱时，会抛出 NullPointerException：

所以：

  • 在业务中如果允许 Integer 为 null，拆箱前务必判空
  • 或在设计上尽量避免使用“既可能为 null 又经常参与运算”的包装类

✅ 学习与面试建议

  • 记清三类字符串的定位：String（不可变）、StringBuilder（单线程可变）、StringBuffer（多线程可变）
  • 熟练常用工具类 API：Math、Random、Arrays、Objects、Collections，至少能说出 2～3 个典型方法和使用场景
  • 必背装箱相关考点：Integer 缓存范围、== 和 equals() 的区别、装箱拆箱的性能与 NPE 风险
