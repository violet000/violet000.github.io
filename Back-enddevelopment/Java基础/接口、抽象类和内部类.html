接口、抽象类与内部类

  • BACK-ENDDEVELOPMENT

一、接口与抽象类概览

1.1 什么是“抽象”？

  • 抽象是对一类事物共同特征的提取
  • 只关注做什么（What），不关心怎么做（How）
  • 在 Java 中，抽象主要通过抽象类和接口来体现

二、抽象类（abstract class）

2.1 抽象类的特点

  • 使用关键字 abstract 声明：public abstract class Animal { ... }
  • 可以包含：
    • 抽象方法（没有方法体）
    • 普通方法（有方法体）
    • 成员变量
    • 构造方法（不能直接实例化，只能被子类调用）
  • 不能被实例化：new AbstractClass() ❌
  • 只能单继承：一个类最多继承一个抽象类

抽象类本身可以没有抽象方法，但一旦某个类中有抽象方法，这个类必须声明为 abstract。

2.2 抽象类的使用场景

  • 作为模板 / 父类骨架存在，抽取多个子类的共性行为和状态
  • 提供部分默认实现，子类可以直接复用或选择重写
  • 常见于“模板方法模式”：在抽象类中定义算法骨架，让子类去实现其中某些步骤

三、接口（interface）

3.1 接口的特点（Java 8 之前）

  • 使用关键字 interface 定义：public interface USB { ... }
  • 用于定义一组规范 / 能力，侧重于“能做什么”
  • 一个类可以实现多个接口（解决多继承能力问题）
  • 成员特性（Java 7 及以前）：
    • 接口中的方法默认是：public abstract
    • 接口中的变量默认是：public static final（常量）

3.2 Java 8 之后接口的增强

Java 8 以后，接口不再是“只能有抽象方法的纯规范”，新增了两种方法：

  • 默认方法：default
  • 静态方法：static

设计动机： 解决“接口升级问题”——在已有接口中新增方法时，不希望所有实现类都被迫立刻修改，可以通过默认方法给出默认实现。

Java 9 之后接口还支持 私有方法（private / private static），用于在接口内部给多个默认方法 / 静态方法复用逻辑。

3.3 接口的典型使用场景

  • 定义标准能力：如 Comparable、Runnable、Serializable
  • 实现面向接口编程（依赖倒置原则），提高扩展性和可测试性
  • 为不同类提供统一的对外行为，而不关心其内部具体实现

四、抽象类 vs 接口（核心对比）

4.1 文字对比

对比项 抽象类（abstract class） 接口（interface）
关键字 abstract class interface
继承 / 实现 单继承 多实现（一个类可实现多个接口）
成员变量 可有普通成员变量 默认是 public static final 常量
构造方法 可以有，供子类调用 ❌ 没有构造方法
方法类型 抽象方法 + 普通方法 抽象方法 + 默认方法 + 静态方法
设计思想 描述“是什么”（is-a 关系） 描述“能做什么”（has-ability 关系）
使用场景 作为父类模板 / 公共骨架 作为规范 / 协议 / 能力扩展

面试常用回答：抽象类更偏“模板”，接口更偏“协议 / 能力”。

4.2 何时用抽象类，何时用接口？

  • 用抽象类：
    • 多个子类之间有明显的共性属性和共同行为
    • 需要提供部分默认实现，并在其中复用代码
  • 用接口：
    • 希望定义一组规范，允许多种完全不同的实现类来实现
    • 需要多继承能力（一个类本身已经有父类，还需要扩展额外能力）

五、接口默认方法与静态方法（Java 8）

5.1 默认方法 default

  • 接口中允许包含带方法体的实例方法
  • 默认方法可以被子类继承，也可以选择重写
  • 主要用于：
    • 接口升级时提供默认实现，避免破坏旧代码
    • 为多个实现类提供通用逻辑

5.2 静态方法 static

  • 只能通过接口名调用：Logger.format(...)
  • 不能被实现类重写

六、内部类（Inner Class）

6.1 什么是内部类？

  • 定义在类内部的类
  • 主要作用：
    • 逻辑分组：将只与外部类强相关的类放在一起，便于阅读和管理
    • 隐藏实现细节：对外部完全不可见，增强封装性

内部类常见 4 种形式：

  1. 成员内部类
  2. 静态内部类
  3. 局部内部类
  4. 匿名内部类

通常用于“只为外部类服务的工具类 / 配置类”，不需要访问外部类的实例成员。

6.4 局部内部类

  • 定义在方法或代码块内部
  • 作用域仅在该方法内有效

局部内部类常配合某些“只在一个方法中用一次的小逻辑”使用，一般在业务中较少直接手写，面试中需要知道概念。

6.5 匿名内部类（重点）

  • 没有名字的内部类
  • 通常用于：
    • 快速创建接口 / 抽象类的临时实现
    • 回调、事件监听等场景，简化代码

在 Java 8 之后，很多匿名内部类可以被 Lambda 表达式替代（前提是函数式接口）。

七、高频面试题（系列 2）

7.1 抽象类和接口的区别？

  • 抽象类是模板，接口是规范 / 能力
  • 抽象类更强调“继承关系（is-a）”，接口更强调“行为能力（can-do）”
  • 接口支持多实现，抽象类只支持单继承
  • 抽象类可以有构造方法和普通成员变量，接口不行（变量默认是常量）

7.2 为什么 Java 不支持多继承？

  • 避免著名的“菱形继承问题”
    • 多个父类有同名方法 / 字段时，子类会产生二义性
  • 简化语言设计与实现，提升可维护性
  • 使用接口多实现来提供“多继承能力”

7.3 接口中可以有构造方法吗？

  • ❌ 不可以
  • 接口不能被实例化，只用于被实现
  • 构造方法的作用是初始化对象 → 接口本身不创建对象，因此不需要构造方法

7.4 抽象类中一定要有抽象方法吗？

  • ❌ 不一定
  • 只要类被声明为 abstract，即使没有任何抽象方法也可以
  • 这种情况一般用于：不希望被实例化，但又想提供部分默认实现的基类

✅ 学习与练习建议

  • 多写代码：各写 2～3 个接口与抽象类的例子（如：支付方式接口、动物抽象类）
  • 画 UML 图：画出抽象类、接口、实现类之间的关系，加深“is-a / can-do”的理解
  • 练习匿名内部类到 Lambda 的迁移：比如将匿名 Runnable 改写成 () -> {...}
  • 在实际项目或练习中，刻意使用“面向接口编程”，体会解耦带来的好处
