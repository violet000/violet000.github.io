面向对象编程（OOP）

  • BACK-ENDDEVELOPMENT
  • JAVA线路学习
  • 面向对象编程OOP

1. 类与对象：OOP 的基本单元

1.1 类的定义

  • 类是对一类事物的抽象：包含属性（成员变量）和行为（成员方法）

1.2 构造方法（无参 / 有参）

  • 名称与类名相同，无返回值类型
  • 作用：在创建对象时初始化状态
  • 可以重载：无参 / 有参多种形式共存

一旦手动定义了任何构造方法，编译器就不会再自动生成无参构造。

1.3 对象生命周期：创建 → 使用 → 回收

  • 创建：new 调用构造方法，在堆上分配内存
  • 使用：通过引用访问对象的字段和方法
  • 回收：不再被引用的对象，由 GC（垃圾回收器）在未来某个时间自动回收

2. 访问控制与 static、内部类

2.1 访问控制修饰符

修饰符 同类 同包 子类 其他包
private ✔ ✖ ✖ ✖
默认（不写） ✔ ✔ ✖ ✖
protected ✔ ✔ ✔ ✖
public ✔ ✔ ✔ ✔
  • 设计目的：控制可见性，保证封装性

2.2 static 关键字

  • 修饰字段：静态变量（类变量）
    • 所有对象共享一份
  • 修饰方法：静态方法
    • 与类相关，而非与某个具体对象相关
  • 修饰代码块：静态代码块
    • 随类加载执行一次，常用于初始化静态资源

静态方法中不能直接访问实例成员，因为此时可能还没有对象。

2.3 内部类总览

  • 成员内部类：定义在类中，依赖外部类实例
  • 静态内部类：static class，类似被包在外部类中的普通类，不依赖实例
  • 局部内部类：定义在方法体内部，仅在该方法中可见
  • 匿名内部类：无名类，常用于创建一次性的接口/抽象类实现

已在“Java 基础”文档详细展开，这里作为 OOP 能力扩展重点记住：内部类是为外部类服务的“隐藏实现细节”的工具。

3. 继承与多态：代码复用与扩展

3.1 继承（extends）

  • 子类继承父类的非私有成员，实现代码复用
  • Java 只支持单继承（一个类只有一个直接父类）

3.2 方法重载与重写

  • 重载（Overload）：同一类中，同名不同参
    • 参数列表不同（个数 / 类型 / 顺序）
    • 与返回值无关
  • 重写（Override）：子类对父类方法进行“重新实现”
    • 方法名、参数列表相同
    • 返回值类型相同或是父类类型的子类型
    • 访问修饰符不能变小

3.3 多态（Polymorphism）与动态绑定

前提条件：

  • 存在继承关系
  • 存在方法重写
  • 用父类引用指向子类对象

调用规则：

  • 编译期：看左边（引用类型）能否调用该方法
  • 运行期：看右边（实际对象类型）执行哪个实现 → 动态绑定

多态让我们“面向父类/接口编程”，运行时自动调用子类实现，是很多设计模式的基础。

3.4 super 与 final

  • super：
    • 调用父类构造方法：super(...)（必须在构造方法第一行）
    • 调用父类方法或访问父类字段：super.method()
  • final：
    • 修饰变量：常量（只能赋值一次）
    • 修饰方法：不可被子类重写
    • 修饰类：不可被继承（如 String）

4. 抽象类、接口、Record 与枚举

4.1 抽象类（abstract class）

  • 可以包含抽象方法 + 普通方法 + 字段 + 构造方法
  • 不能直接实例化，只能被继承
  • 适合提取多个子类的共性骨架 / 模板

4.2 接口（interface）

  • Java 8 前：只允许抽象方法和常量
  • Java 8+：允许 default / static 方法
  • Java 9+：允许 private 方法（接口内部复用逻辑）
  • 主要表示“能做什么（能力）”，支持多实现

常用区分：抽象类更像“模板”，接口更像“规范 / 能力”。

4.3 Record（JDK 14+）

  • 用于快速定义不变数据载体类（类似 DTO）
  • 编译器自动生成构造方法、equals、hashCode、toString

只在你使用的 JDK 版本支持时考虑使用，适合表示简单值对象。

4.4 枚举（Enum）

  • 表示有限个固定常量，如状态值、权限级别等
  • 本质是一个继承自 java.lang.Enum 的类

5. 封装与对象交互

5.1 Getter / Setter 与封装

  • 字段私有化，通过公开的 getter/setter 控制访问

好处：校验、日志、权限控制都可以集中在 setter / 方法中完成。

5.2 this 关键字

  • 指向当前对象本身
  • 常用于：
    • 区分成员变量与方法参数同名
    • 构造方法链调用：this(...) 调用同类中其他构造方法

5.3 值传递 vs 引用传递（Java 只有值传递）

  • Java 中所有参数传递都是“值传递”
    • 基本类型：传递的是“值的拷贝”
    • 引用类型：传递的是“引用的拷贝”（指向同一个对象）

常见误区：Java 没有 C++ 那种“引用传递”，只有“值传递”，只是这个值有时是“引用”。

5.4 静态初始化块

  • static { ... }，在类加载时执行一次
  • 常用于复杂静态字段初始化（但要避免写复杂逻辑）

6. 包与模块化（package / module）

6.1 包（package）

  • 用于对类进行命名空间划分，避免类名冲突，组织项目结构
  • 包名一般与目录结构对应：com.example.project.service
  • 规则：全小写，层级由业务域到具体模块

6.2 import 使用

  • 引入其他包中的类或静态成员
  • import static 可导入静态方法字段：如 import static java.lang.Math.*;

6.3 模块化（Java 9+）

  • 使用 module-info.java 声明模块
  • 明确导出包（exports）与依赖模块（requires）
  • 目标：改善大型项目的封装与依赖管理

在日常应用开发中，模块化主要出现在较新 JDK 与大型工程 / 框架中；初学阶段理解概念即可。

7. 注解与元数据（简要）

7.1 注解的作用

  • 为类 / 方法 / 字段添加结构化元数据
  • 供编译器、框架或工具读取并执行特定行为（校验、扫描、映射）

7.2 元注解回顾

  • @Target：注解可以用在什么元素上
  • @Retention：保留到什么阶段（源码、字节码、运行时）
  • @Documented：是否生成到 Javadoc
  • @Inherited：子类是否继承父类的注解

在 OOP 语境下，可以把“注解 + 反射”看作是一种“配置式面向对象扩展”方式。
