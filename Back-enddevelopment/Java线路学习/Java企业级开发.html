1. Web 开发基础与主流框架

1.1 Servlet 与 JSP（传统 Java Web）

  • Servlet
    • Java 服务器端组件，负责处理 HTTP 请求 / 响应
    • 生命周期：init() → service() → destroy()
    • 通过 HttpServletRequest / HttpServletResponse 操作请求与响应数据
  • JSP
    • 早期用于在 HTML 中嵌入 Java 代码，生成动态页面
    • 现代开发中更推荐使用前后端分离或模板引擎（Thymeleaf, Freemarker）替代

现代企业开发中，Servlet/JSP 更多作为历史概念与底层原理存在，具体开发主要交给框架（如 Spring MVC）封装。

1.2 Spring Boot（主流企业开发标准）

  • Spring Boot = Spring Framework + 自动配置 + 内嵌容器（如 Tomcat）
  • 特点：
    • 开箱即用的自动配置（spring-boot-starter-*）
    • 内嵌 Tomcat / Jetty，main 方法即可启动 Web 服务
    • 与 Spring 全家桶（Spring MVC / Data / Security / Cloud 等）深度整合

1.3 其他 Web 框架（了解）

  • Quarkus：面向云原生与 GraalVM 的高性能框架
  • Javalin：轻量级、函数式风格 Web 框架
  • Play Framework：受 Rails 启发的全栈框架，多用于 Scala/Java

实际企业项目中，Spring Boot 仍是绝对主流，其他框架可做拓展了解。

2. 构建与依赖管理：Maven / Gradle / Bazel

2.1 Maven（最常用）

  • 基于 pom.xml 的项目管理工具
  • 管理：
    • 依赖（dependencies）
    • 构建生命周期（编译、测试、打包）
    • 插件（maven-surefire-plugin、maven-compiler-plugin 等）

2.2 Gradle

  • 使用 Groovy 或 Kotlin DSL 的构建工具
  • 语法更灵活、可编程性强

2.3 Bazel（了解）

  • Google 开源的大型代码仓库构建系统
  • 优势：可扩展、适合超大规模单体仓库、多语言
  • 在一般 Java 项目中较少见，企业级平台/基础设施团队较多使用

入门和中小型项目首选 Maven 或 Gradle；面试中了解差异和常见命令即可。

3. 依赖注入 DI 与 Spring 生态

3.1 DI / IoC 核心思想

  • 控制反转（IoC）：对象不再自己创建依赖，而是由容器负责创建并注入
  • 依赖注入（DI）：通过构造器、setter 或字段注入依赖对象

好处：

  • 降低耦合度，便于测试与替换实现（如切换数据源、Mock 等）
  • 配合注解与配置，使得业务代码更专注于业务逻辑

3.2 Spring 核心注解（常用）

  • 组件定义：
    • @Component：通用组件
    • @Service：业务服务层
    • @Repository：数据访问层（DAO）
    • @Controller / @RestController：Web 控制器
  • 依赖注入：
    • @Autowired：自动注入（字段 / 构造器 / setter）
    • 推荐构造器注入，更利于测试与不可变设计

3.3 Spring Boot 自动配置

  • 通过 spring-boot-starter-* 引入功能模块
  • 根据 classpath、配置文件（application.yml）等条件自动装配 Bean
  • 可以通过 @SpringBootApplication（组合注解）开启组件扫描与自动配置

面试常问：“什么是 IoC / DI？Spring 是如何实现的？”、“构造器注入 vs 字段注入？”、“自动装配的大致机制？”

4. 数据库访问与事务

4.1 JDBC（底层标准）

  • Java 提供的数据库访问标准 API
  • 操作步骤：
    • 加载驱动
    • 获取连接 Connection
    • 创建 PreparedStatement
    • 执行 SQL，处理 ResultSet
    • 关闭资源

直接使用 JDBC 代码量大且易出错，实际项目中通常通过 ORM 或模板封装（如 Spring JDBC、JPA）。

4.2 ORM：Hibernate / JPA / Spring Data JPA

  • Hibernate：主流 ORM 框架，JPA 规范的常见实现
  • JPA（Java Persistence API）：定义了 ORM 的标准注解与 API
  • Spring Data JPA：
    • 在 JPA 基础上再做封装
    • 通过接口方法命名自动生成查询（findByNameAndStatus）

常见注解：

  • @Entity、@Table
  • @Id、@GeneratedValue
  • @Column、@OneToMany、@ManyToOne 等

4.3 事务与事务传播（Spring）

  • 使用 @Transactional 声明事务边界
  • 对应事务特性：ACID（原子性、一致性、隔离性、持久性）
  • 传播行为（简要）：
    • REQUIRED（默认）：有则加入，无则新建
    • REQUIRES_NEW：总是开启新事务
    • NESTED：嵌套事务（受数据库和平台支持限制）

面试常问：“@Transactional 在 Spring 中是如何实现的？”、“为什么事务只在 public 方法上生效？”（代理机制）

5. 日志系统：SLF4J、Logback、Log4j2

5.1 日志门面与实现

  • SLF4J：日志门面，定义统一接口
  • Logback / Log4j2：具体日志实现
  • 通过绑定实现（如 logback-classic）将 SLF4J 调用映射到具体实现

5.2 基本用法

5.3 日志级别与配置

  • 常见级别：TRACE < DEBUG < INFO < WARN < ERROR
  • 通过配置文件控制输出位置（控制台、文件）、格式、滚动策略等
    • Logback：logback.xml
    • Log4j2：log4j2.xml / yml

企业级项目中，日志是问题排查的生命线，务必养成合理记录日志的习惯。

6. 测试与调试

6.1 单元测试：JUnit / TestNG

  • JUnit：事实上的 Java 单元测试标准
  • TestNG：更灵活的测试框架，支持依赖测试、参数化等

6.2 Mock 与隔离：Mockito

  • 通过模拟依赖（Repository、远程服务等）隔离被测单元
  • 常见用法：when(...).thenReturn(...)、verify(...)

6.3 接口测试：REST Assured

  • 用于编写针对 HTTP API 的自动化测试
  • 可验证响应状态码、Body、Header 等

6.4 行为驱动测试：Cucumber

  • 使用 Gherkin 语法（Given/When/Then）描述场景
  • 更偏业务人员可读，适合作为需求与测试桥梁

6.5 压力 / 性能测试：JMeter

  • 模拟多用户并发访问接口
  • 分析响应时间、吞吐量、错误率等指标

企业级开发中，单元测试 + 集成测试 + 性能测试是质量保障三板斧。
