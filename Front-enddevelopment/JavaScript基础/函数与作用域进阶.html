函数与作用域进阶

目标：彻底吃透函数的声明/调用/作用域/闭包/this，能在真实业务中写出可维护、无坑的函数代码。

1. 函数基础与声明方式

1.1 函数声明（Function Declaration）

  • 语法：function foo() { ... }
  • 提升规则：整体被提升，函数体可在声明前调用。
  • 适用场景：公共工具函数、需在文件顶部就能调用的函数。

示例：

1.2 函数表达式（Function Expression）

  • 语法：const foo = function() { ... };
  • 提升规则：只提升变量声明，函数值不会提升，声明前调用会报错。
  • 适用场景：需要控制创建时机、避免过度提升导致的调用混乱。

示例：

1.3 命名函数表达式

  • 语法：const foo = function bar() { ... };
  • 作用：bar 仅在函数内部可见，便于递归或调试堆栈。

1.4 参数默认值与剩余参数

  • 默认值只在实参为 undefined 时触发（null 不触发）。
    • function f(x = 1) {}；f(undefined) 得 1，f(null) 得 null。
  • 默认值是惰性求值：每次调用都会重新计算表达式。
    • function f(x = Date.now()) { ... } 每次调用拿到新的时间戳。
  • 解构结合默认值：防止解构 undefined 报错。
    • function createUser({ name = '匿名', role = 'guest' } = {}) {}
  • 剩余参数 ...rest 必须在形参末尾，得到一个真数组。
    • function sum(base, ...nums) { return nums.reduce((a,b)=>a+b, base); }

1.5 箭头函数 vs 普通函数

  • 箭头函数特点：
    • **没有自己的 this**，沿用定义处的外层 this（词法绑定）。
    • **没有 arguments**，需用剩余参数 ...args。
    • **不能 new**，没有 prototype，也不能做构造函数。
    • **不能用 yield**，不能是生成器。
  • 适用场景：回调、高阶函数、需要捕获外层 this 的情况。
  • 不适合：对象方法（需要动态 this）、构造函数、类方法需要原型时。
  • 返回对象字面量要加括号：const fn = () => ({ value: 1 });

1.6 小结与易错点

  • 需要提升：用函数声明；需要延迟创建/避免提升：用函数表达式。
  • 需要 this 语义：用普通函数；需要捕获外层 this：用箭头。
  • 默认值只对 undefined 生效；剩余参数是数组，arguments 是类数组。

2. 高阶函数、回调与递归

2.1 高阶函数是什么

  • 定义：接收函数作为参数，或返回一个函数。
  • 价值：复用控制逻辑、抽象操作、组合行为（map/filter/reduce）。

2.2 常见内置高阶函数

  • map：逐个变换，返回新数组。
  • filter：按条件保留，返回新数组。
  • reduce：累积器模式，可做求和、分组、统计。

3. 作用域、执行上下文与闭包

3.1 作用域类型

  • 全局作用域：在任意地方可见（浏览器全局是 window）。
  • 函数作用域：var 声明的变量仅在函数内可见。
  • 块级作用域：let/const 声明在最近的花括号 {} 内有效；有暂时性死区。

3.2 执行上下文与调用栈

  • 每次调用函数都会创建执行上下文，入栈；返回后出栈。
  • 查找变量时，先看当前上下文的作用域，再沿着作用域链向外层父作用域查找，直到全局；找不到报 ReferenceError。

3.3 闭包（Closure）是什么

  • 定义：函数“记住”了它被定义时的词法作用域环境，而不是调用时的环境。
  • 直观理解：函数把外层变量“打包带走”，即使外层函数早已返回。

示例：计数器

3.4 闭包的常见用途

  • 数据私有化：外部只能通过函数访问内部状态。
  • 惰性计算/缓存：如 memoize。
  • 函数工厂：根据配置返回行为不同的函数。
  • 模拟模块：早期 IIFE + 闭包实现私有变量。

3.5 闭包常见坑

  • **循环与 var**：for (var i=0; i<3; i++) setTimeout(()=>console.log(i)); 会输出 3、3、3，因为 var 共享一个函数作用域。解决：用 let 或用 IIFE：
  • 内存占用：闭包长时间存在会持有外部变量引用，不再需要时将引用置为 null 或让闭包出作用域。

4. 特殊函数特性

4.1 IIFE（立即执行函数表达式）

  • 作用：立刻创建一个独立作用域，避免全局变量污染。
  • 形式：

4.2 arguments 对象

  • 类数组，有 length 和按索引访问，但没有数组原型方法。
  • 箭头函数没有自己的 arguments（会从外层捕获），建议直接用剩余参数。
  • 转数组：const args = Array.from(arguments); 或 [...arguments]。
  • 与剩余参数区别：arguments 包含所有实参，剩余参数只收集未被单独声明的那部分。

4.3 严格模式 "use strict"

  • 开启方式：文件顶部或函数内部写 "use strict";；ESM/模块脚本默认严格模式。
  • 主要影响：
    • 禁止隐式创建全局变量（未声明直接赋值会报错）。
    • 普通函数独立调用时 this 为 undefined（非严格模式是全局对象）。
    • 删除不可删属性会抛错，重复参数名会抛错。
    • with 语句被禁用。

5. this 的绑定规则（逐条对照记忆）

5.1 决定 this 的唯一因素：调用位置

按优先级从高到低：

  1. new 调用：this 指向新创建的实例。箭头函数不能 new。
  2. 显式绑定：call / apply / bind 指定的对象。
  3. 隐式绑定：作为对象的方法被调用，obj.fn() 中 this 是 obj。
  4. 默认绑定：独立函数调用，非严格模式下是全局对象，严格模式下是 undefined。
  5. 箭头函数：没有自己的 this，直接用定义处外层的 this，且无法被以上方式改变。

5.2 事件处理中的 this

  • DOM 事件处理器（非箭头）默认指向触发事件的元素。
  • 在类/组件中用箭头函数做回调，可捕获实例 this，避免手动绑定。

5.3 call / apply / bind

  • call(thisArg, ...args)：即时调用，参数逐个传。
  • apply(thisArg, argsArray)：即时调用，参数数组传。
  • bind(thisArg, ...preset)：返回一个永久绑定 this 与部分参数的新函数（常用于事件回调、定时器）。

5.4 函数借用（Function Borrowing）

  • 借用数组方法处理类数组：
    • const arr = Array.prototype.slice.call(arguments);
    • Array.prototype.forEach.call(nodeList, cb);
  • 适合 DOM 的 NodeList、arguments 等类数组对象。
